# AGENTS.md

WorkStream is a "humans x virtual employees" collaboration desk: a Vite static frontend plus a single Edge Function backend. Before changing code, read the "Repository layout" section of [docs/guide.en.md](docs/guide.en.md) and [docs/arch/scheduler.en.md](docs/arch/scheduler.en.md). Every rule in this file must point at an implementation in this repo or at a gate; a rule that cannot point at one does not belong here.

## Environment and gates

- **Node must be 22.12+; `engines` is `>=22.12.0 <23`.** The system Node on this machine is v24 and gets stopped by [scripts/check-node.mjs](scripts/check-node.mjs) in `preinstall`/`predev`/`prebuild`. Prefix every `npm`/`npx` call with `export PATH="/d/tools/node22:$PATH"` (portable Node 22).
- **`npm run qa` is the only full gate** (= check-node + check-schema + smoke). Run it before merging a change; it reports in the thousands: `dev/smoke.mjs` drives the real handler against a local fake database, and **865 checks, 0 failures** is the current floor -- it may only rise.
- **`npm run build` = `tsc --noEmit && node scripts/build.mjs`**; type checking lives in the build, not in qa.
- **This repo has no ESLint configuration**: do not run `npx eslint`, do not suggest adding a linter in place of a static cross-check. When an invariant needs to be machine-verifiable, write it the way `dev/check-schema.mjs` is written -- a static reconciliation plus one `check()` in `dev/smoke.mjs`.
- Start the server with `--worker` (or `WORKSTREAM_WORKER=1`): [functions/worker.mjs](functions/worker.mjs) is the resident scheduler loop; without it progress depends on the frontend polling one slice every 5 seconds, and the inbox stops the moment the page is hidden (see [dev/local-function.mjs:17](dev/local-function.mjs#L17)).
- The frontend calls the backend only through the same-origin `/functions/v1/app?action=<name>`, with the session token in the custom header `x-workstream-token`; hit the local dev function server in exactly that form too -- a `POST` to `/app` without `action` only returns `missing_action`.

## Conventions

- **Registration is the effect, and `register()` must return a precise disposer.** Any new registry (tools, prompt blocks, file renderers, action routes) is undone by calling the function it returned, and `dev/smoke.mjs` has to prove the undo is clean: register -> assert present -> dispose -> assert absent. See [functions/mcp.mjs:734](functions/mcp.mjs#L734): a tool that the declaration lists but the registry lacks throws on the spot instead of surviving until runtime as a `tool_not_allowed`.
- **Order is an allocated resource, not the sequence of source lines.** Prompt-block positions live in the slot table at [functions/prompt.mjs:23](functions/prompt.mjs#L23): each block claims an `order` and declares `volatile` (whether it changes every round), and assembly sorts "stable blocks first, blocks that change every round last", because provider-side prefix cache matches the longest prefix from the start -- one volatile block parked in the middle makes everything after it pay again each round. Adding a block means taking a number from the table, not pushing onto the end of an array; the memory block already learned this lesson, and the ascending concatenation in [functions/engine.mjs:598](functions/engine.mjs#L598) exists precisely so it does not break an older prefix. Smoke test 8d holds this invariant ([dev/smoke.mjs:1035](dev/smoke.mjs#L1035): the common prefix of two rounds must cover the entire previous window, with a reusable ratio >=95%), and 8d2 pins the breakpoint itself ([dev/smoke.mjs:1060](dev/smoke.mjs#L1060)).
- **Whatever the model sees must be reconstructible.** If something enters the request body, it has to be rebuildable from `run_steps` or from the transcript: usage columns are written through the single `usageColumns` in [functions/steps.mjs:53](functions/steps.mjs#L53), the prompt slots this step used land in their own `prompt_slots` column ([functions/engine.mjs:765](functions/engine.mjs#L765)), and the trajectory's "Context" tab lists the blocks around each breakpoint from it. Add a class of model-visible input and the same round must produce a trajectory step for it, otherwise the backend can never explain why it answered the way it did.
- **Chain of thought never enters the stream.** `reasoning` goes only into step detail ([functions/engine.mjs:762](functions/engine.mjs#L762)); the stream body carries only `content`, and the single place to read reasoning is the "Reasoning" tab of the step inspector ([src/views/agents/StepInspector.tsx:208](src/views/agents/StepInspector.tsx#L208)). This is a product red line, not a style preference: a colleague's internal reasoning appearing in the group is a leak.
- **Bad configuration fails loudly, not with a WARN.** A silent failure the self-check cannot cover does not count as fixed. [functions/mcp.mjs:747](functions/mcp.mjs#L747) throws "declared but not implemented" at cold start, and `dev/check-schema.mjs` reconciles migration columns against the columns the code actually reads and writes -- because the local fake database is JSON storage, where a misspelled column simply runs. Missing references, unknown enum values, mismatched format versions: reject the whole entry and report the reason honestly (`normalizeTools` in `functions/plugins.mjs` and `normalizeIndex` in `functions/registries.mjs` both return lists of `skipped` reasons); no silent skipping and no quiet renaming for compatibility.
- **Limits apply to the complete result, not to a fragment.** Bytes, characters, counts and deadlines can only be enforced once the value that actually goes out is visible: the 512KB in [functions/plugins.mjs:18](functions/plugins.mjs#L18) accumulates bytes per chunk including wrapping and metadata, and the 6000 characters at [:19](functions/plugins.mjs#L19) are truncated only after the `text` parts are assembled. When you test, test three cases: exactly at the limit, slightly over, and one chunk that alone exceeds it.
- **Publish state only at the commit point.** Claiming a task is a compare-and-write (`db.mail.claim`), and cleanup closes the steps that were never opened properly (`closeOrphanSteps`); never write an intermediate state as a terminal one before success.
- **Opaque ids must carry their origin.** Ids coming from outside always go through `uuid(value, name)` at [functions/util.mjs:66](functions/util.mjs#L66), and the error message has to say which field it was; new internal ids use `newId()`. Do not add module-level `current` / `active` / `selection` singletons -- shared state belongs on a service object that has an owner.
- **Do not re-validate a boundary types already prove.** Validate at real boundaries: request body entry points (`text` / `int` / `oneOf` / `avatarData`), external addresses the user types in ([functions/util.mjs:163](functions/util.mjs#L163) `safeApiBaseUrl`: https only in production, private networks and metadata addresses allowed only with `WORKSTREAM_DEV=1`), writes to storage, egress, cross-process calls. No defensive fallbacks between functions inside one process, and no tests for inputs static types already exclude.
- **A knob that varies with deployment cannot be hardcoded.** Context budgets, timeouts and limits go through `Config`/parameters/env (`CONTEXT_CHARS_DEFAULT` at [functions/util.mjs:85](functions/util.mjs#L85), the master key via `WORKSTREAM_DATA_KEY`). A `DEFAULT_*` constant or a test hook does not count as configurable. Protocol constants, external specifications and security invariants stay fixed.
- **New behavior hangs on an extension point; the main loop does not change.** Tools go into `TOOL_HANDLERS`, actions into each module's `actions` table ([functions/handler.mjs:75](functions/handler.mjs#L75) answers `unknown_action` for anything else), prompt blocks into the slot table at [functions/prompt.mjs:23](functions/prompt.mjs#L23), backend channels into the list at [functions/backends.mjs:20](functions/backends.mjs#L20) ("does this channel accept tools" is a single `caps.tools` field read by both the prompt wording and the tool injection; a transport declared in the list but missing an implementation is thrown at cold start by [functions/agents.mjs:380](functions/agents.mjs#L380)), stream-file previews into the renderer registry at [src/lib/fileRenderers.mjs:25](src/lib/fileRenderers.mjs#L25) plus one line registered in [src/lib/renderers/index.mjs](src/lib/renderers/index.mjs) (a forgotten registration is caught statically by `npm run check:schema`; the UI's "model source" dropdown is reconciled against the backend list in `dev/check-schema.mjs` too -- smoke tests cannot see the UI), and UI languages into the `LOCALES` table at [src/lib/i18n.ts:15](src/lib/i18n.ts#L15) plus a dictionary in `src/locales/<id>.json` with the same key set (dictionary key sets and placeholders, the keys the message-lookup sites use, and the server-side id whitelist at [functions/locales.mjs:4](functions/locales.mjs#L4) are all reconciled by `dev/check-schema.mjs` -- the server bundle cannot import frontend TS, so the list exists twice, which means a gate has to keep the two from disagreeing). Changing the dispatch loop in `functions/engine.mjs` means updating [docs/arch/scheduler.en.md](docs/arch/scheduler.en.md) in the same change.
- **A choice the UI offers must actually take effect.** Languages with `complete: false` in `LOCALES` are only listed under "coming soon" and are not clickable: picking one and still seeing Chinese, with no error anywhere, is worse than not offering it (`dev/check-schema.mjs` pins "complete implies a dictionary"). Under the same rule, the theme in the top bar and the language dropdown on the settings page both write the account preference immediately (`auth.patch`) -- there is no second path that says "now press save".
- **Every sentence that reaches the screen belongs in the dictionary; the half the dictionary check cannot see is held by the ratchet.** Every piece of copy the user reads in the UI (including the text for server error codes in [src/api.ts](src/api.ts), mapped to dictionary keys by `ERROR_KEYS`) must have an entry in `src/locales/*.json`; data, enums and fallback sentinels may stay Chinese, but each one has to be listed in `BARE_COPY_CEILING` in `dev/check-schema.mjs` and you have to be able to say why it is not copy. This gate is a **ratchet that may only fall**: it counts non-comment Chinese lines per file, a rise means new hardcoded copy went on screen, and a fall without editing the table is rejected too -- otherwise the table turns into a debt list that gets more fictional over time. The dictionary reconciliation can only prove "every key the lookup sites use exists in the dictionary", not "there is no Chinese in the UI that never entered the dictionary", and a sentence that missed the migration looks perfectly normal in Chinese and only shows up when the user switches to English -- something a smoke test hitting the API never sees. Error codes have their own reconciliation: codes written literally in `functions/*.mjs` must have a key in `ERROR_KEYS`, while the class users actually run into is written nowhere as a literal -- it is a template assembled from a variable (`invalid_<field>` from the validators, `registry_<reason>` from remote fetches, `skill_skipped_<reason>` per skipped skill, `<table>_request_failed` named after the table). That check first recognises code-shaped templates by shape (exactly one "${…}", both static segments left with only `[a-z_]`), then expands the variable against a table of where its values come from, and looks the real codes up in the copy -- pinning three more things: any function that builds a code must be registered in the signature table, a registered value source that yields no value must be reported, and shapes that look like codes but are not must be listed in `NOT_CODES` with an explanation of what they are (`call_<id>` is a tool call id, `<field>_clipped` is a length field in the trajectory) -- a new way of building codes outside the table, or an old signature nobody calls anymore, both report on the spot. The lookup-site scan and the bare-copy scan share one `srcFiles` list, and that list has a **discovery floor** (one each for file count and for key count): when the glob degrades or lookups move to variable keys, "half as many keys" reads like "nobody hardcoded anything" and the ratchet's delta actually looks better -- neither false pass raises an error, only the discovery count tells the truth. Dictionary values must also contain no zero-width characters, BOM or bidi isolates (non-breaking spaces excepted -- French punctuation before-spacing is legitimate typography): they slip in beside the copy invisibly, and then the sentence someone pastes is no longer the same string as the dictionary entry. **Server-side sentences that reach the screen are the other half of the same rule**: the stream system lines and the demo employee's conversational text live in the two template sets of [functions/copy.mjs](functions/copy.mjs), chosen at write time by the actor's `prefs.lang` (never picked falls back to Chinese, an explicit other language falls back to English), and section 7c of `dev/check-schema.mjs` scans both write shapes -- the `insertMessage` helper and a raw `db.messages.insert` -- for hardcoded Chinese, with a discovery floor on the site count so a mismatched scan reports instead of passing empty. Bypassing the helper is exactly how the VM-grant broadcast stayed Chinese through the whole i18n batch: it was written straight to the table, so it was outside the only gate that looked, and it also dropped three columns the helper fills.
- **Problems that only surface after switching language get pinned at source shape, not in screenshots.** A Chinese sentence ends with `。` and separates itself, a Latin script needs a space: two lookup expressions placed adjacently in JSX look fine in Chinese and render as `…follows it.No delegate…` in English (the delegate line in the stream settings drawer really did lose a space once). Section 7b of `dev/check-schema.mjs` recognises the shape -- two adjacent lines that are each a `{…}` lookup child with no `{" "}` between them report on the spot, as do two lookups side by side on one line. Width is the same class of problem: German compounds push fixed-width controls into truncation, `npm run check:schema` cannot see that, and only the "narrowest container + both themes" screenshot protocol can.
- **Registration is a side effect, deregistration must be exact.** A register function returns a disposer that removes only its own entry: re-registering the same id throws instead of silently overwriting, and a registration missing fields throws at the point of listing (`npm run qa` section 24 locks all three). Do not build a registry for something that contributes nothing at runtime -- a declarative slot table is enough.
- **Migrations are append-only.** Under `sql/`, create the next incrementing number (the series currently runs 0001->0014) and never edit a published migration; a new column does not redefine the semantics of existing rows. Run `npm run check:schema` afterwards.
- **Write assertions in pairs.** Every "privilege escalation rejected" check needs a counterpart of "the owner doing the same thing succeeds", otherwise an owner comparison that only reads id columns passes forever and is a false pass.
- **Tests describe behavior, not correctness.** When behavior changes, change the test in the same commit and state in the delivery notes why.
- **Repeated values of the same kind should be symmetric first.** Asymmetry you cannot justify is usually a missed extraction.

## Secrets and commits

- The **values** of API keys, PATs, session tokens and `auth_cipher`/VM passwords are never echoed: not in logs, not pasted into the conversation, not in screenshots, not in docs or test fixtures. The API returns a masked tail only (`maskKey` at [functions/util.mjs:197](functions/util.mjs#L197)), and encrypted columns never appear in any read endpoint's column list.
- **No credentials in a plaintext column.** Some fields are plaintext by design (`vms.gateway_url` holds the ttyd gateway the browser dials directly; the server does not proxy the session, so there is nothing to seal). For such a field, clamp the shape at the write point: `gatewayOf` at [functions/vms.mjs:197](functions/vms.mjs#L197) accepts only ws/wss/http/https, and rejects any URL carrying `user:pass@`, a query string or a fragment with `gateway_url_no_credentials` -- letting a user paste a token into the address means transcribing the password into a permanently plaintext database.
- **Commit or push only when the user explicitly asks.** Before committing, scan the staged content for secrets; `git add` only the files you changed, never `git add -A`; after `git commit`, verify with `git status`; before pushing, confirm the remote with `git ls-remote`.
- Secrets come from environment variables and site Secrets (`WORKSTREAM_DATA_KEY`, `WORKSTREAM_SMTP_URL`), whose values are entered through site settings; verification that needs a real upstream key is supplied by the user, never fabricated.

## Frontend and visual acceptance

- **A frontend change is not finished until it has actually been looked at in a browser.** Screenshots must cover at least the **narrowest container** and **both light and dark themes** (the theme is controlled by `<html data-theme>` and can be preseeded through `localStorage`'s `workstream.theme`). Screenshot scripts live in `dev/_shots/` (gitignored).
- Prefer components from `src/lib/ui.tsx` and the shadcn/Tailwind CSS under `vendor/`; do not add a new UI library. For existing dependencies such as `recharts` or `cmdk`, check whether they can be reused first.
- **One color has exactly one decider.** SVG colors computed from data go on the element attributes, and a CSS selector must not set the same property again -- author styles beat presentation attributes, so pastel nodes with near-white labels become invisible in the dark theme (`npm run check:schema` locks exactly this: `.ws-drawio text`).
- Do not stack a navigation button on an area that is clickable as a whole; distinguish list rows by a small type tag, not by splitting the list into type sections.
- Numbers and units on screen must be able to prove their own measurement basis: if it cannot be measured, say "not reported" -- never pass 0% off as a result (see how the Stream flow cache-hit bar does it).

## Comments and documentation

- Code comments are written in Chinese and state **only the why**: a hidden constraint, a subtle invariant, the workaround for a specific bug. Do not restate what the code does, do not explain distant behavior, do not leave review history behind.
- The commit that changes behavior also updates the corresponding README or guide section and JSDoc; one fact has exactly one home.
- **Every browsable document exists as a Chinese/English pair with a switch line at the top** (`README.zh.md`/`README.md`, `CHANGELOG.md`/`CHANGELOG.en.md`, `docs/guide.md`/`docs/guide.en.md`, `docs/arch/scheduler.md`/`docs/arch/scheduler.en.md`), and an English file links to English files. This file and [PROVENANCE.md](PROVENANCE.md) are deliberately single-language: AGENTS.md is read by agents and by whoever edits the repo, and a rules file kept in two languages becomes two rules files that drift. Section 9 of `dev/check-schema.mjs` keeps the pairs from drifting on their own: it compares shape, not blessed hashes -- heading level sequence, table row and cell counts, body size, inline-code and link sets, and the switch link in both directions. Inline code and link targets are facts, not copy, so they stay byte-identical apart from shorthand a document invents for itself, which is registered with its English spelling in that section's alias table; Chinese left untranslated in an `.en.md` reports on the spot, since a sentence missed in the translation is exactly the kind that looks fine until someone switches language. An `.en.md` without its Chinese twin, or a single-language document not declared in the exception table with a reason, reports too. Translating a document is not a change to the fact it states: when a fact moves, both languages move in the same commit.
- No metaphors. Before writing "contract", ask whether there is a more precise word (response field, JSON validation, ESM export).
- Exactly one newline at the end of every file.

## Changing this file

Keep every rule self-contained and linked to the implementation or gate it points at. An invariant that can be made machine-verifiable in `dev/smoke.mjs` or under `scripts/` should become a gate rather than a spoken rule -- spoken rules expire when people leave, gates do not. A new rule must name which real failure in this repo it prevents; if it cannot, delete it.
