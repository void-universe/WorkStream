## 自检

```sh
npm run qa     # = node scripts/check-node.mjs && node dev/check-schema.mjs && node dev/smoke.mjs
npm run build  # = tsc --noEmit && node scripts/build.mjs
```

- `dev/smoke.mjs`：真实 handler + 本机假数据库跑端到端检查——注册与验证、头像的存取与成员/现场透出（含内置默认头像那一档 WebP 收得下、SVG 被拒）、SSRF 拦截、两级 memory、技能市场与上下文注入、远端技能源（本机 fixture HTTP 服务当源：加源、搜源、装快照、源上涨版本后复查出「可更新」、更新换正文、源不可达时的如实报错、index 格式与同源/重定向边界）、云端 Agent 后端（本机假 QCA：建档与控制台链接取 id、PAT 只回尾号、自检只读模型清单、令牌不对时报 `qca_access_denied`、@ 派发到回群、思考链不进群、上下文压平成一条正文、environment 与 session 的复用与作废、三种失败形态、插话掐断交出半截正文、后端与地址成对、经分流口的一次性提问不落进群里那条 session）、Stream Server 规范 v1.0.0 那一档（本机假执行器与参考实现对着跑：规范表自洽与十几处当场拒的形状、路径参数编码后才拼进路由、发现响应缺的格按档位默认补齐、两档都声明时优先分时那一档、建档时问清是哪一档并写回档案、改令牌被对方拒了不把一次故障钉成永久判决、自检如实报出对方声明了什么、分时档一轮的帧序与权威正文、群工具整个发过去、一轮任务里不重新发现、令牌不对时连存在的那条路也回 401、重放同一个 turn_id 被拒、叫停交出半截正文而不是错误帧、上游静默与迟迟不吐第一个字都叫得停、流断了先问服务器那一轮成没成再认输、turn 表有条数上限与 TTL、表满时拒新的而不砍在跑的那一轮、请求体超限在读满之前就拒、专属档复用对方那侧同一条 session 且思考链不进群、caps 与档位说反时整条描述符退回）、符合性测试套件（考卷先考自己那台参考实现与夹具：分时档零 fail 且真考到了流与在跑那一轮被叫停、档判错时专属档的检查一条也不跑、专属夹具两轮都读到权威正文且思考链不算进字数、只认 OpenAI 兼容的那台发现即 fail 且档内检查全 skip 而不拿猜测当考分、考卷的分片器与客户端共用的那一个同字节同结果）、在线自检的入口闸（同一个来访地址两次起跑必须超过 10 秒、连点不续期、同一地址同时只跑一轮、跑完不等于没跑过）、后端清单、群与审批、@ 派发、替身、排程、交付物、上游坏德性、跨群归并、未读/处理中/已读投递状态、签名与员工现场可见性、时间片公平、压缩、内部工具与对外 MCP 的读写边界、成员管理、会话隔离、`site.meta`，以及部署适配层只允许自定义令牌头这一条边界。项数以 `npm run qa` 收尾那行为准，**1072 项通过、0 项失败**是当前地板，只许涨。
- `dev/check-schema.mjs`：把 `sql/*.sql` 的列定义与 `functions/*.mjs` 实际读写的列对账（本机假数据库是 JSON 存储、不校验列名，列名写错只能靠这道静态检查兜住）。同一道检查还核对群文件渲染器有没有登记、`functions/backends.mjs` 的后端清单与界面「模型来源」下拉及 `type Backend` 联合是否一致，以及界面语言的两份清单（`src/lib/i18n.ts` 与 `functions/locales.mjs`）：id 集合相同、标成「已完成」的语言真有字典、四份字典的键与 `{}` 占位符和中文源一致、界面 `t("…")` 取到的键真的存在。它还钉住四件事。一是**界面文案裸奔棘轮**：按文件数非注释的中文行，比 `BARE_COPY_CEILING` 里记的大就是新加了一句没进字典的硬编码文案，变小却没改表同样拒绝。二是**服务端错误码与前端文案对账**：`functions/*.mjs` 里字面写得出的码都要在 `src/api.ts` 的 `ERROR_KEYS` 里有一个键；按变量拼出来的码会按取值来源表逐个展开——校验器按字段名拼的 `invalid_<字段>`、远端抓取失败的 `registry_<原因>`、技能源逐条跳过原因的 `skill_skipped_<原因>`、`store.mjs` 按表名拼的 `<表>_request_failed`——没配文案就把内部字段名或表名直接贴到屏幕上；长得像码但不是码的拼法登记在 `NOT_CODES` 并写明凭什么（`call_<id>` 是工具调用号、`<字段>_clipped` 是轨迹里的长度字段）。三是**并排两句文案之间要有分隔**：两个取词表达式紧挨着排，中文界面一切正常、切到英文就渲染成 `…follows it.No delegate…`。四是**可浏览文档的中英配对**：标题层级、表格行列、正文规模、内联码与链接集合，以及两个方向的切换链接；英文那份里留着没翻译的中文当场报。

## 群与 Stream 面板

首页把群铺成卡片网格或列表，右上角可切 2/4/9 分屏，几个群并排放在一张工作台上，每格都能直接 @ 派活；建群与凭 UUID 进群从面板顶栏打开。虚拟员工、Market、调度台、虚拟邮箱、虚拟机与设置都在顶部导航条。群边框会跟着任务状态闪：**黄色**表示群里被 @ 派了活、任务还在排队等时间片，**绿色**表示虚拟员工刚领到并推进过这个群（跑完的绿色会保留几秒）。节奏按「人」的体感定——黄色 0.65s（≈运动心率），绿色 1.8s（≈放松心率）——每个群可以在 设置 → 闪烁颜色 里单独换这两档颜色，偏好只存在本机。输入框里的 @ 按钮，或者自己打出 @所有人，一次点名群里的每位虚拟员工：各落一封任务、各显示一条投递状态；替身不在广播范围里（它替的是某一位真人，广播不是冲那位主人来的），暂停中的员工也不接。

群聊右侧是两块可收缩的卡片。**群公告**可发布/清空、显示更新时间，非管理员只读。**群文件**可在线预览、下载、上传、删除，按文本入库、上限 400KB；上传会在时间线里播报一条系统消息，`.drawio` 流程图在线预览时画成结构图（只还原节点、连线与标签，样式和坐标精度不还原），其余类型按纯文本预览；「设置 → 群公告」只留一句指引，避免两处编辑同一个字段。两块卡片下面才是 成员 / 虚拟机 / MCP / 设置 四个标签。虚拟员工这一轮交出的群文件会以**交付卡片**挂在 ta 的回复下面（文件名、大小、类型加一句交付说明），整块可点，点开就是群文件页里那份原件的预览；只交了文件、正文一个字没写的那一轮照样发卡片，此时那条消息只有卡片没有气泡。公告与文件的所有操作都能用 MCP 工具完成（见下方「技能与 MCP」）。

群里授权过、且填了控制台网关地址的机器会在顶栏多出一个 **SSH 控制台** 入口，群设置抽屉「接入本群的机器」那一栏的每一行也能直接点开它：宽窗口是真分屏（左边聊天与输入框照常用，右边是 iTerm 那样的终端），窄容器里终端整块盖住群、关掉就回来。控制台连的是那台机器上的 ttyd 网关，推荐用 `ttyd -p 7681 tmux new-session -A -s work` 起——这样你和虚拟员工 attach 的是同一个 tmux 会话，你可以一边 `dmesg -wT`、`ls` 看现场，一边 watch ta 的操作。远程桌面不在这条链上。

## 虚拟员工与投递状态

真实员工与虚拟员工都可以设置头像：在 设置 → 账号 或在「虚拟员工」档案里上传图片，浏览器会裁成 128×128 的 WebP 存进库，群里、成员列表、调度台与顶部导航都会跟着换；不设置就退回名字首字。手边没图也可以点上传按钮下面那一排内置默认头像（男生：短发 / 侧分 / 眼镜，女生：长发 / 齐肩 / 马尾）——图是写在 `src/lib/avatars.ts` 里的 SVG，点下去才在浏览器烤成同一档 128×128 WebP，所以入库字段、`avatarData` 校验和上传那条完全一样，仓库里不放任何头像图片文件。

点任意虚拟员工的头像会进 `#/agents/<id>` 详情页：看 ta 的虚拟邮箱正在处理哪条消息、还排着几封，头像角上转圈表示在忙，签名以「」小字挂在头像旁。每条 @ 消息旁边标着这个员工的投递状态——排队 = **未读**，开跑 = **处理中**，跑完 = **已读**，失败/取消单独标出。签名主人可以在「虚拟员工」页改，员工自己也能在工具回路里用 `set_signature` 更新。非主人打开详情页时只看到群成员本就能看到的资料与共同群里的现场，Key、系统提示词与记忆不会出现。

「正在处理哪条」下面画了一张 **Stream flow**：横轴是邮件进入时间片的时间，纵轴按群权重从高到低排；每封邮件是一条长条，处理中是带流动高光的黄色长条，已读按群上色，未读是虚线，失败标红。窗口自动取最近 15 分钟或 24 封，主人和群友看到同一张图（群友只含共同群）。卡片底部有一条 **缓存命中** 统计：把轨迹里每一步的 `input_tokens / cached_tokens` 按群加总，给按 token 加权的总命中率（不是每轮百分比的平均）和分群命中率，框选一段时间就只看那一段。口径写在 `src/lib/usageStats.mjs`（`.mjs` 是为了让 `dev/smoke.mjs` 能把同一份实现直接 import 进来，而不是在测试里再抄一遍算法）：上游没回报用量的轮（被插话掐断的、QCA 云端与演示后端）不进分母，报得自相矛盾的轮在落库那一步就按不回报收成 `null`（`functions/agents.mjs` 的 `normalizeUsage`），一条用量都没有时直接写「这条后端不回报用量」，不拿 0% 冒充。

## 替身

替身只**代答**、不**代收**。在 设置 的「替身」卡里选一位自己名下的虚拟员工，生效时机选「立即开始」或「某个时间段」（最远排到 90 天后，两端也可以只填一头），这份班表对 ta 名下所有群一起生效。群里 @ 那位真人时，@ 通知照旧投给真人（虚拟邮箱或真实邮箱），替身只是**额外**接一封任务。落群的回复署名仍是替身自己，气泡上标一条「替 @X 代答」，这个标记来自 `messages.on_behalf_of`，不是把名字改成真人。群设置抽屉里可以只在这一群开或关、或换成另一位员工。是否生效在派发那一刻按时钟算，不到点去改状态：时段一结束自然就不再代答，不需要任何常驻进程保证那次「关牌」发生。替身必须属于本人、状态在跑、且已经在这个群里——借别人的员工代自己说话等于让第三方读你的群上下文，会被当场拒掉。

「AI 替身」是这件事的一键形态：设置里的 AI 替身用一台已登记的部署 server 建一条隐藏员工（`agents.kind='standin'`），绑在你的账号上，并把它加进你在的所有群——之后你新进的群，在派发那一刻补进去——开关打开期间 @ 你的消息由它代答。它不是你的员工：不出现在员工列表里，可选的时段就是上面那条替身班表。

## 排程

虚拟员工还能**按排程自己干活**，不用等人 @。在 调度台 的「排程」卡里给某个（员工, 群）排一条「每隔多久」（1 分钟到 7 天）或「每天几点」（时刻 + 勾选周几 + UTC 偏移，默认带出本机偏移并标「本机」，半小时档也带得进），再写下要办的事（上限 2000 字）。保存后条上直接显示服务端算出来的往后三个对点、上次跑的时刻与累计合并的对点数。到点这一轮走的还是那条时间片管道：排程只是往那位员工的邮箱多投一封信，并发槽、CAS 领取、插话、压缩全部复用。有人在线等回答时先答人，排程留到下一轮按时钟追上来；这一轮没事要说可以只回空正文，WorkStream 不会替你往群里发一句「本次无内容」。每人最多 20 条、最短间隔 1 分钟——排程是主动干活，不是往群里灌消息的定时器。暂停就是把时钟那一列写空，界面随即显示「下一次 —」而不是装作还在跑，改文案也不会替你打开亲手停掉的排程。删排程会把队里还没跑的那一封一起撤回（正在生成的那封让它跑完，掐断是插话的活）。员工被移出群时那条排程自己停掉，删员工或解散群则连带删掉挂在他/这个群名下的排程。排程只能给自己名下的员工、自己所在的群排——借别人的员工排班等于烧别人的 Key，会被当场拒掉。

## 全局记忆（dreaming）

同一个人的虚拟员工常常同时在几个群里干活，而每个群的历史各自折叠成自己那一份摘要——跨群的事实（「这个项目月底交付」「上次说好用 psql 不用 ORM」）散在各群摘要里，没人合并。**全局记忆（dreaming）** 把该主人名下各群当前的压缩摘要喂给模型一次，并成一份属于这个人的全局记忆，下一轮以独立的一块回到 ta 名下每个群的上下文里（它排在缓存断点之前，稳态下逐字复用，不给每轮添开销）。入口有三个，走的都是同一条归并：**群历史一折叠完就顺手归并**（调度台那张「全局记忆」卡上的开关，挂在人身上而不是员工身上，因为并出来的那份属于人）、**按排程定时归并**（新建一条「到点归并全局记忆」的排程，这一类正文是额外交代不是必填，到点不进群说话）、以及**这里手动跑一次**。三个入口共用一个去重：同一个人同时只允许一封归并信在队。水位线按（员工, 群）各记一份——同一个群里两个人各折一份摘要时，只按群记会让后写的盖掉前一条的序号，那条要么每轮重并、要么被当成已归并而永久漏掉。一次装不进输入预算的那几份如实记成「这一步没并进去」，水位不推，下一轮它们还是新素材；上游报错或回了空正文等于一个群都没并进去，水位线一个字段都不写，也不会覆盖别人先落成的那一份（比较并写）。跨群隐私是硬边界：那份记忆只给模型用来判断，抬头那句写死「别把别的群的细节念给这个群听」，它不进群聊正文，别人读自己那份读到的是空。

## 技能与 MCP

内置技能写在 `functions/skills.mjs`，不入库、不可卸载、始终注入每个虚拟员工的上下文：**WorkStream 平台技能**（建群、拉员工、邀请真人、发消息、登记与授权虚拟机、读群历史与公告）和 **DevStream 群文件与公告**（群文件的浏览、预览、上传、删除与公告读写的完整参数，含对外 MCP 的 `tools/call` 示例）。两个公共默认技能（周报与进度同步、会议纪要与待办）按固定 id 幂等补齐，新员工建档时自动安装。

Market 是一张目录页，三张入口卡分别进三个分区：**技能**、**员工**、**插件**（卡上的数字只报读到的，读不到写「未上报」，不拿 0 冒充）。**技能**默认不展开详情：一行行条目带名称、版本、分类、一行摘要与 `.md` 下载链接，点开才看正文。本地市场（本站上传：可公开、可设为新员工默认技能、可顺手装给指定员工）与远端技能源各占一个子列表，搜索按名称/摘要/分类命中后同样只列条目。安装对象有三档：只装给某位员工、装给现有全部员工，或「现有 + 以后新建的员工」（这一档等于把技能标成默认，新员工建档时自动装上）；员工详情的「技能」标签也能搜本地市场和远端源，但那里装到的只给当前这一位，卸载也在这个标签。内置技能不显示安装控件——它对每个员工始终启用。**员工**是一组内置岗位模板（回归验收 / 需求拆解 / 文档维护 / 排期跟进）：先选建档目标（已登记的部署 server，或演示端点），再点「雇佣」，名称、职责与系统提示词按模板一起填好，建完直接落到详情页补 Key 或换模型；模板本身不带凭据，凭据永远属于账号。**插件**接入外部标准 MCP 服务（JSON-RPC over HTTP）：服务端探测 `tools/list` 并缓存工具清单，这些工具会并进主人名下所有虚拟员工的工具清单，调用照样走同一条工具管道并落进轨迹。令牌只存密文、界面只回尾号，端点按 SSRF 规则校验（线上只收 https，`WORKSTREAM_DEV=1` 才放行内网）。每人最多 12 条连接器、每条最多 24 个工具，工具名与内置工具重名时内置优先。

远端技能源（`functions/registries.mjs`）是主人自己添加的地址：每人最多 8 个、单源最多 200 条。一个源就是一份 `schema: 1` 的 index JSON——`{ name, skills: [{ slug, name, summary, category, version, body_url }] }`——`body_url` 指向同一台主机上的 `.md` 正文，所以一个放 `index.json` + 若干 markdown 文件的 GitHub 仓库/静态站就能当技能源用。版本号是纯展示口径，比对时点分数字按段比大小（`1.10` 新于 `1.2`），比不动的非数字版本只要不相等就算有更新。远端装的语义是「抄一份快照」：安装或更新的那一刻把正文写进本地 `skills` 行并记下来源（`source_registry_id` + `source_slug`）与版本，之后上游怎么改都不影响正在用的员工。每位主人 + 源 + slug 只有一条快照行，被多个员工共用，所以「更新」是一次替换正文、所有装了它的员工同时换新。员工详情打开「技能」标签会按源各拉一次 index 自查版本（也可点「复查版本」）；有更新的条目在已装列表里标出目标版本并给出「更新」按钮，某个源暂时打不开时只提示「这些远端技能暂时比不了版本」，不影响已装内容的注入。抓取边界：index 与正文都限时限字节（256KB / 200KB）、拒绝重定向、正文必须与 index 同源、线上只收 https。

员工工具回路可用：`search_history / read_window / list_files / read_file / upload_file / delete_file / present / get_announcement / get_context / list_skills / read_skill / list_my_resources / set_signature`，以及以主人身份执行的 `send_message / create_stream / add_agent_to_stream / invite_member / set_announcement / register_vm / grant_vm`。写操作按主人在群里的角色与资源归属校验；`set_signature` 只改员工自己的签名，不对外部 MCP 开放。`present` 把本群的一个群文件标成这一轮的交付物，只在员工回路里有意义——卡片要挂在这次回合的那条回复上，外部 MCP 的调用不属于任何回合，所以它不进对外清单。

对外 MCP 端点（`POST /functions/v1/app?action=mcp`，`x-workstream-mcp-key` 认证）作用域固定在该群，暴露 13 个工具：群历史、上下文、公告读取、群文件的列表/读取/上传/删除，以及 `send_message / invite_member / set_announcement / list_skills / read_skill`；建群、登记与授权虚拟机只在员工工具回路内可用。

## 云端 Agent 后端（Qoder Cloud Agents）

「虚拟员工」页的**模型来源**默认是 **Stream Server 规范入口**：建档时先问对方的发现接口，按声明落分时或专属档；只认 OpenAI 兼容的地址自动退回自建端点那一档，不用重新建档。自建 OpenAI 兼容端点与 **Qoder 云端 Agent** 要显式选：选云端时员工不再自己带模型，而是挂 Qoder Cloud Agents 上已有的那个 agent。建档时粘 `agent_…` 或整条控制台链接都行（`https://qoder.cn/cloud/agents/agent_xxx` 会取出 id），地址栏切到云端会自动填上 CN 区 origin（换区或私有部署再改），令牌填 Qoder 设置 → 个人访问令牌 里新建的 `pt-…`，照样 AES-GCM 密封入库、界面只回尾号。换后端必须同时填新令牌——自建端点的 `sk-` Key 在云上不认，服务端直接以 `agent_key_required_for_backend` 挡下。

这条通道与自建端点有三处不同，都是刻意的：

- **上下文的权威在 WorkStream**：每轮把 common 记忆、本群记忆、摘要水位线之后的窗口和技能说明压成一条 `user.message` 送过去（角色分段标出，超过 90 万字符在出网前就挡下）。云端 session 只当云端侧的对话缓存，按 (员工, 群) 各存一条在 `app.qca_sessions`，所以不同群不会在云上串台；员工被移出群、改绑别的云端 agent、换地址或换令牌，对应的缓存一律作废重建。后台压缩那一轮走一次性 session，「帮我摘要」不会混进群对话史。
- **工具回路在云端**：不注入我们的群工具，云端 agent 用它自己的工具集。因此它的上下文里那句技能说明会改口——「WorkStream 工具在这一通道里调不到，不要把工具名写进回复，需要落地的动作列成待办」，免得照着技能正文假执行一次 `send_message`。
- **思考链不进群**：先连 SSE 再发问，只取规范 `agent.message` 里 `type=text` 的块，thinking 与工具块一律丢掉。半截增量只用来在群里被插话时交出打断点之前的正文；流走光还没等到规范回复就如实报 `qca_stream_ended_unfinished` / `qca_no_reply`，不拿增量冒充回帖。云端报错、限流、令牌失效都映射成 `qca_*` 错误码进轨迹，界面与自建端点用同一套「这次没能完成」提示。轨迹检视器的「思考链」页是看它的唯一入口：后端没回传 reasoning 时那页显示一句「这一段是空的」，不留一块空白让人以为是加载坏了。

插话与叫停两条通道同口径：每收到一个分片、以及每次静默满 800ms 都问一次要不要停。云端 agent 在自己那边跑工具时可以整段不吐增量，只在分片边界检查会把打断拖到 180s 整轮超时——两条后端的 `Interrupted` 都交出打断点之前的半截正文。上游坏德性两条通道同一口径：SSE 走到尽头既没 `[DONE]` 也没 `finish_reason`，自建通道报 `upstream_stream_incomplete`，和云端的 `qca_stream_ended_unfinished` 是同一件事——半截正文一个字都不进群，这轮结为失败。非 2xx 在出网那一步就翻成有名字的码（`upstream_server_error` / `upstream_rate_limited` / …），邮箱与轨迹里不再落一个裸的 `"500"`；同一句话在错误码清单里只有一个家。没有任何一条路会把 `failed` 重新排队，所以群里那句写「要再试请重新 @ 他」，不写「稍后会自动重试」。自检第 28 节用故障开关（500 / 空流 / 半截，按跑切换、不靠触发关键词）钉住这些，并配一条拨回正常后重新 @ 能跑成的对照。

后端差异写在一张清单上：`functions/backends.mjs` 里每条通道带自己的 transport 与 `caps.tools`，「这条通道吃不吃工具」只有那一个字段说了算——提示词怎么措辞、引擎发不发工具清单、要不要去查主人的连接器，都读同一份。表里声明的 transport 在 `agents.mjs` 的 `TRANSPORT_ROUTES` 缺实现，冷启动就抛；界面「模型来源」下拉的选项由 `npm run check:schema` 跟清单对账。内置演示端点是这张表的第三条通道：它不是员工档案上的一个选项，`api_base_url` 等于 `demo://local` 时从地址认出来，因此「云端后端 + 演示地址」与「规范入口 + 演示地址」这类跑不通的组合在建档与改档都被挡下（`qca_needs_real_origin` / `stream_needs_real_origin`）——演示与云端都不靠默认猜一档，要显式选后端。连通测试（`agents.test`）在云端只拉一次模型清单，确认令牌与地址成对，不建 session、不动用量；其余通道走引擎同一个分流口发一条极短对话。真实云端联调需要一个 `pt-…` 令牌，自检套件用本机假 QCA 覆盖同一条链路（`dev/smoke.mjs` 第 23 节），清单本身的形状与解析规则另有第 8d3 节。

## 主题、界面语言与品牌

明暗两种主题由 `<html data-theme>` + Tailwind `dark` 变量控制，`index.html` 里的首帧脚本按 localStorage 偏好或系统偏好先行设置，避免闪白。顶部导航的 `>_` 可以在 设置 → 品牌标样式 里切「实心块」或「嵌入式」——嵌入式是透明底，暗色白字、亮色黑字——偏好只存本机。版权信息 `copy right www.void-universe.com` 写在 About 页与登录页脚。

界面语言按名义 GDP 前 26 国的官方/通用语言去重后列出 **18 种**（IMF WEO 2025 年数、2026 年 4 月版：en、zh-Hans、de、ja、hi、fr、ru、it、pt-BR、es、ko、tr、id、nl、ar、pl、sv、he）。这批语言由一份清单决定、落在两处：前端 [src/lib/i18n.ts](../src/lib/i18n.ts) 的 `LOCALES` 带 id、自称、书写方向与「译完与否」，服务端 [functions/locales.mjs](../functions/locales.mjs) 只带 id 白名单（Edge Function 打包不了前端 TS，所以存两份，`npm run check:schema` 逐字对账这两份的 id 集合、四份字典的键与占位符、以及界面取到的每个键是否真有译文）。**第一次进入站点先问一次语言**（按浏览器语言预选，选哪种整屏文字当场跟着变），登录后写进 `users.prefs.lang` 并在下次冷启动读回——账户偏好优先于本机偏好，换设备不用再选一次。目前只有简体中文、英语、德语、日语四种译完，覆盖面是**整个界面的文案**：选语言这一步本身、登录与注册、验证链接落地页、顶部导航、设置，以及聊天、虚拟员工、排程、技能与插件、轨迹检视各页——连服务端回的错误码（`upstream_rate_limited`、`schedule_not_owned`，以及校验器按字段名拼出来的 `invalid_token`、数据库连不上时按表名拼出来的 `users_request_failed` 这一族）也翻了，因为「这一轮没跑成」的原因是最需要看懂的一句话。剩下 14 种在「即将上线」里列名但点不了：给了选项却仍显示中文，用户不会收到任何报错，这比不提供更糟；阿拉伯语与希伯来语还要等从右到左排版那一批（`<html dir>` 现在恒为 `ltr`）。

**界面文案翻完了，服务端生成的正文分两半。** 落进群里的系统行与演示员工的会话体回复，在写入那一刻按操作者的 `users.prefs.lang` 定，中英两套模板集中在 [functions/copy.mjs](../functions/copy.mjs)（没设过语言的回落中文，显式选了德语日语这类的回落英文——读得懂英文的概率远高于读得懂中文）；虚拟邮箱信件、压缩与归并摘要仍是中文，设置页那行说明就是这么分的，不假装它们已经跟着翻译（就地标记要后端在消息上带出口径，见 [CHANGELOG.en.md](../CHANGELOG.en.md) 待办表）。系统行按写入者定语言，代价是群成员语言不一致时显示的是操作者那一种：彻底的做法是存结构化事件、由前端按各自 locale 渲染，那要给 messages 加列并回填历史行。

## 后端怎么跑

浏览器只调用同源的 `/functions/v1/app?action=<名称>`，不带任何平台凭据。会话令牌通过自定义头 `x-workstream-token` 传递——站点适配层会剥掉前端的 `authorization` 与 `cookie`，所以这两个头不能用来携带应用层凭据（`dev/smoke.mjs` 第 11 节直接跑真实 `serveSite` 验证了这条边界）。

鉴权在应用层完成：PBKDF2-SHA256 口令散列（15 万轮）、sha256 后的会话令牌（30 天）、AES-GCM 密封 API Key 与虚拟机口令（主密钥优先取 `WORKSTREAM_DATA_KEY`，没有就落在 `app.runtime_state` 一行里）。密文列只在服务端读取，接口只回 Key 尾号。用户自填的 API 地址过 SSRF 白名单：线上只接受 https，拒绝内网与元数据地址。

调度有两种驱动方式，走的是同一条 `scheduler.tick`。边缘函数不能驻留，所以纯站点部署由前端每 5 秒轮询推进一格（页面隐藏时跳过）；本机/自建部署可以加 `--worker`（或 `WORKSTREAM_WORKER=1`）拉起 `functions/worker.mjs` 的常驻循环，不开前端也能推进邮箱。每个虚拟员工按各群权重（群主/管理员确认，默认均分）用最大余额法分配这一格的预算，任务用比较并写领取，跑着的孤儿任务由过期回收兜住，员工之间互相 @ 的层数上限是 3。替身代答不另开一条路：它只是在派发那一刻多投一封普通 `mail`，时间片、CAS 领取、插话、压缩全部复用。排程同样不另开一条路：到点的排程在同一个 tick 里被投成信，而 worker 在没有一封排队信时也会去扫一次到期行（只看「有没有排队信」的话，一个安静的群永远攒不出第一封，到点的排程就只会躺在表里等一个不会来的触发）；推进那条时钟用的是比较并写，前端轮询、常驻 worker、多实例 Function 同时看见同一行也只有一个赢，投递失败则把时钟回拨成自己刚读到的值，下一轮重新判到点。

## 把员工迁到远端执行器

员工是一行记录，不是一个进程：群、邮箱、记忆、技能与投递标记都在 WorkStream 库里，只有「这一轮怎么调模型」发生在执行器上。所以迁移搬的是执行器，不是员工本身。`scripts/migrate.mjs` 在已经配好免密 ssh 的那台机器上执行——Edge Function 没有原生 TCP，产品自己永远不开这条连接。

前提是员工已经在 Stream Server 档（`backend=stream`）：这个工具只搬执行器，不改它手里没有的 OpenAI 兼容 Key。先在界面上选一次 Stream Server 入口，指向本机的参考执行器（`node dev/stream-server.mjs 8300`，配 `WORKSTREAM_STREAM_UPSTREAM_*` 与 `WORKSTREAM_STREAM_SERVER_TOKEN`）。

```sh
# 迁到一台已经能免密 ssh 的机器
node scripts/migrate.mjs --employee <id> --to root@10.0.0.5 \
  --public-url https://box.example.com \
  --upstream-url https://api.example.com/v1 --upstream-key <key> --upstream-model <model>

# 迁回本机：执行器会用新令牌重新拉起来
node scripts/migrate.mjs --employee <id> --to local --upstream-url <url>

# 只看计划，不复制、不启动、不改档案
node scripts/migrate.mjs --employee <id> --to root@10.0.0.5 --public-url <url> --dry-run
```

命令按顺序做这些事：`ssh ... node -v`（必须是 22.12–22.x）、把 `functions/*.mjs` 与执行器入口复制过去（远端不装 npm）、跑 `node .../launcher.mjs install|chmod|start`、在本机探测公网地址的发现响应，最后只发一次 `agents.update`。发现会在这条请求里再跑一次：远端从 WorkStream 那侧连不上时改档失败，员工继续用旧地址，不会停在半切换状态。

从 A 迁到 B 就是同一条命令换一个 `--to`：上游地址、模型与 key 会经 ssh 从 A 的配置里读回来，所以 B 调的是同一个模型，切换落地后 A 会被停掉（`--keep-source` 留着当备用）。记忆、技能、会话记录与下一轮的上下文从来没离开过数据库——分时执行器是无状态的，每一轮都把内容带在请求里——迁移唯一可能丢掉的是还在跑的那一轮；工具会等邮箱安静下来再停旧进程。

两条路都得通：本机能到那台机器（工具探测），WorkStream 的 Function 也能到（改档时再探）。`http://` 与内网地址默认被拒，`--allow-http` 才放行（对应服务端的 `WORKSTREAM_DEV=1`）；执行器自带 Bearer 令牌，公网机器前面要套 TLS。

想在没有模型的情况下走完这条路，`node dev/fake-openai.mjs 8795` 是一个最小的 OpenAI 兼容上游，把 `--upstream-url` 指到 `http://127.0.0.1:8795/v1` 即可。

执行器是一个脱离终端的 Node 进程（`launcher start`），日志 `executor.log`、状态 `executor.state.json` 都放在它自己的目录里；`launcher stop` 与 `launcher status` 可以单独调用。自检钉住的是决策（地址规则、Node 下界、令牌与上游必填）；ssh 那一段需要真机，`npm run qa` 不覆盖它。

## 部署 server

一台分时执行器服务多个员工，所以它的地址登记一次就够，不用每个员工重填一遍：员工表单里的部署 server 下拉列出已登记的那些，「新增 server」当场填名称、执行器地址与 Bearer 令牌。登记时会立刻探一次发现——答不上来、或答的不是规范那套，就不会存下来——并把答案（shared、dedicated、或退回 OpenAI 兼容那一档）一起记下。

选中一台 server 会把它的地址、令牌与档位复制进员工档案。这份复制是有意的：删掉 server 不会弄坏已经建在上面的员工，改 server 也不会悄悄把谁重新部署一遍。设置页列出已登记的 server，带最近见过的时间与模型数量，并提供「测连接」与「删除」。

登记本身不起任何进程：执行器必须已经在那台机器上跑着。把它放上去的是 `scripts/migrate.mjs`（见上一节，走 ssh），而且它不要求这台 server 先被登记。

## 上下文预算与压缩

员工表单里的上下文是一根按档位停的滑杆——4k、8k、16k、32k、64k、128k、256k、512k、1M、2M、4M、8M token——档案里存的仍是字符，按每 token 2 字符折算（`agents.context_chars`，上限 16M）。旁边那个压缩水位（`agents.compact_at`，10–100%，默认 95）说的是历史窗口最多吃掉这份预算的多少：95 表示快满了才折，10 表示一开头就折。

水位是触发线，不是保留比例：在这条线以内窗口保留原文，超过之后最旧的那部分被折成摘要，`covers_through_seq` 记下摘要覆盖到哪一条。所以同一个模型上的两位员工可以折得勤慢不同，但一轮能看到的东西不变。

## 群文件、目录与素材

群文件是一棵树：每一行存 `path`（父目录，根为空）和 `name`，目录就是 `store='dir'` 的一行——空目录因此能真实存在。路径规则统一在 `functions/fs.mjs`（不许 `..`、不许空段、最多 6 层），上传、改名和员工工具走同一套，同一目录内名字唯一。移动目录会重写整棵子树的 `path`，删目录连子树一起删。

文件到底是什么由 `store` 说：`db` 是库里的文本（400KB 上限），`link` 是任意格式的外链（预览按 `content_type` 直接渲染图片和视频），`storage` 是平台桶里的对象、走签名下载地址。没有注入 Storage 时，真正的二进制上传无处可去——请求体上限 5MB——所以今天的大视频诚实的做法是存一条外链；等部署能开 Storage，那条路代码里已经在了。

员工通过 `list_files` 与 `read_file` 看到的是同一套路径，所以人建的目录对模型不是隐形的。
